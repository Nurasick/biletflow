## Conventions

Decided once, applied to every table. Not revisited per-slice.

| Concern | Decision | Why |
|---|---|---|
| Primary keys | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Small indexes, readable in `psql`, cheap joins |
| Public identifiers | A **separate extra column**, only where the spec exposes one | See below |
| Money | `amount_minor BIGINT` + `currency CHAR(3)` default `'KZT'` | §7. Matches payment-provider APIs, which all speak integer minor units |
| Timestamps | `TIMESTAMPTZ`, never naive `TIMESTAMP` | An instant is not a wall-clock reading |
| Event-local time | `events.timezone` holds an IANA name (`'Asia/Almaty'`) | §4.11 — calendar exports must preserve the event's timezone |
| Enums | `VARCHAR` + **named** `CHECK`, mirrored by a Python `StrEnum` | Native PG enums have `ALTER TYPE` restrictions, and Alembic autogenerate misses value changes |
| Table names | **plural**, `snake_case` | Also dodges reserved words — see below |
| FK column names | singular: `event_id`, not `events_id` | |
| Audit rows | append-only; no `UPDATE`/`DELETE` in the service layer | §4.16 — entries "shall not be editable or deletable" |
| Soft delete | **none.** Use the explicit states the spec names | §4.3 `is_hidden`, §4.12 `status='suspended'` |

Constraint names come from the `naming_convention` already set on
`Base.metadata` in `app/db/base_class.py`. Because the `ck` template references
`%(constraint_name)s`, **every `CheckConstraint` must be given an explicit
`name=`** or SQLAlchemy raises at import time.

### Primary keys vs public identifiers

These are two different things. A table can have both.

| Table | PK (internal, for FKs) | Public column (extra) | Required by |
|---|---|---|---|
| `tickets` | `id bigint` | `public_code` — `BF-3K9P-22XM` | §4.7, printed on paper tickets |
| `orders` | `id bigint` | `order_number` — `BF-241130-0042` | §4.13, quoted in support cases |
| `events` | `id bigint` | `slug` — `jazz-night-almaty` | §4.11, stable calendar URL |
| everything else | `id bigint` | *none* | |

**Foreign keys always point at the bigint.** The public column never appears in
a FK. It exists so that URLs, printed tickets, and support conversations don't
leak or depend on internal IDs.

`users` deliberately has no public column: no endpoint takes a user ID from an
untrusted caller. The client reads `/users/me` and the ID is derived from the
token.

Ticket QR codes do **not** depend on `public_code` being unguessable. §4.7
demands a *tamper-resistant* QR, which comes from an HMAC signature — see
[qr-codes.md](qr-codes.md).

### Reserved words

Postgres reserves `user`, `order`, and `row`. Plural table names solve the first
two (`users`, `orders`); the seating table is `venue_rows`. Without this you
would double-quote those identifiers in every raw query forever.

## Roles are relationships, not a column

§1.3 names four roles. Only one is a global property of a user.

| Role | Represented as | **Not** |
|---|---|---|
| Attendee | Any user — or no user at all (guest checkout) | a flag |
| Organizer | Has a row in `organizer_profiles` | a flag |
| Event Admin | Has a row in `staff_assignments` **for that event** | a flag |
| Platform Admin | `users.is_platform_admin` | — |

This matters. Organizer and Event Admin are **scoped to an event**. A single
`users.role` column cannot express "admin for event 7 but an ordinary attendee
for event 9" — which is exactly what §4.8 requires when the mobile app shows
"only assigned events."

So authorization always asks *"what is this user's relationship to this
event?"*, never *"what is this user's role?"*

Details and the permission matrix: [01-identity.md](01-identity.md).

## Working rules

- **One slice, one Alembic migration.** Do not batch two slices into one.
- **Every model module must be imported in `app/db/base.py`** or
  `--autogenerate` silently produces an empty migration with no error.
- **Read every generated migration before applying it.** Autogenerate cannot
  detect renames — it emits `drop_column` + `add_column`, which destroys data.
- **Test the downgrade** while the slice is still small.
